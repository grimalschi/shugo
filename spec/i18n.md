# Internationalization

The document describes how the site is assembled in several languages. In the first version, this is not: below is a sentence compiled after studying Astro, SvelteKit with Paraglide, Next.js with next-intl, Nuxt i18n and Hugo.

## Decisions

Nothing yet.

## What others do

| | One page file in all languages | Where do the lines come from | Default language address |
| --- | --- | --- | --- |
| Astro | no: Folder on the tongue | no catalogues, handwritten | without prefix |
| SvelteKit + Paraglide | yeah. | `messages/en.json`, function per line | configurable |
| Next.js + next-intl | yeah. | `messages/en.json`, ICU format | with prefix |
| Nuxt i18n | yeah. | files on the language, format vue-i18n | without prefix |
| Hugo | no: file or folder per language | `i18n/en.toml`, number shapes by CLDR | without prefix |

- Four out of five draw one pattern in all languages and read the strings by function. Astro, where the file is in the language, does not give line directories at all.
- The address is most often this: the default language without a prefix, the rest under `/<language>/`.
- The plural is different for everyone.
- The general trap is "current language" as a hidden state. With static assembly, there is no request from which to take it, and the language of one page can flow into another.

## Proposal

### Configuration

```json
{
  "site": "https://example.com",
  "i18n": {
    "locales": ["en", "es"],
    "default": "en",
    "prefixDefault": false
  }
}
```

English uses `/about` and Spanish uses `/es/about`.

### One page in all languages, language is a clear value

Each page file is calculated once per language. Language is not a hidden state, but a field: `Shugo.locale`.

```
<!-- pages/products/[slug].shugo -->
---
import { getProducts } from "@/lib/shop"

export async function getStaticPaths({ locale }) {       // call for each language
  return (await getProducts(locale)).map((product) => ({
    params: { slug: product.slug },                        // each language has its own address.
    key: product.id,                                       // linking translations of one page
    props: { product },
  }))
}

const { product } = Shugo.props
const { t, locale } = Shugo
---
<h1>{product.title}</h1>
<p>{t("product.inStock", { count: product.stock })}</p>
<time>{new Intl.DateTimeFormat(locale, { timeZone: "America/New_York" }).format(product.date)}</time>
```

A page that is not in any language says this: `export const locales = ["en"]`.

### Lines

```json
// locales/en.json
{
  "nav.home": "Home",
  "product.inStock": {
    "one": "{count} item in stock",
    "other": "{count} items in stock"
  }
}
```

- The keys are flat, substitutions in braces.
- A plural message is an object keyed by CLDR category. Shugo selects the category from `count`. English uses `one` and `other`. Include the count in the message.
- `Shugo.t("key", { … })` reads the language string of this page.

### What is checked during assembly

The assembly stops if:

- the key is not in the default language;
- in the line of another language, there are no substitutions;
- in the object of plural there is no form that this language needs;
- the key is not a string written in code, but is calculated.

If the key is not in another language, the default language string is taken, and a list of such keys appears in the report.

### What framework gives itself

- `Shugo.alternates` is the same page in other languages: `[{ locale, url }]`. It is used to make the language switch and `hreflang` tags.
- `Shugo.localeUrl("/about", "es")` is the address of a page in another language.
- There are no redirects to the browser language: Google advises not to do them.

### Incremental updates

Combining data downloads and expressions ([1](decisions.md#1-data-loading-and-expression-are-counted-together-go-compares-the-result)) helps here: you do not need to track which block you read which keys. You changed one translation line - all pages are recalculated, and only those blocks where this line is shown are recorded.

Common blocks:

- A component that does not read a language or a string remains one in all languages.
- the component that causes `Shugo.t` or reads `Shugo.locale` becomes common to the language: the language is included in its name.

### What is not in the offer

- Language file (`about.es.shugo`). The markup is split between copies, and each structure change is a revision in several places. If the page in another language is arranged differently, this is a separate file with `export const locales = ["es"]`.
- ICU format. It is more expressive, but it is the second syntax inside the lines of JSON, and it is harder to check it when assembling.
- Domain on the tongue.

## Open questions

- Do you agree with the “one page per language and line approach in JSON”?
- The default language prefix.
- Line Format: An object with number forms like here, or ICU if the strings are going to go into translation services.
- Where long texts live: Articles and descriptions come from data in their own language, not from line directories.
- Letter from right to left: `dir` on `<html>` and logical properties of CSS.
